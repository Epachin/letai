# SkyWay — десктопное приложение для Windows

Новая версия проекта из архива «1 микро.rar»: **3 микросервиса + RabbitMQ + общая SQLite-база + интерфейс PySide6**.

> При наличии `TRAVELPAYOUTS_TOKEN` поиск авиабилетов использует Aviasales Data API
> (ранее найденные цены). Без токена сохраняется встроенный каталог. Отели используют
> локальный каталог. Внешние системы продажи билетов, гостиничные системы и банковский
> эквайринг не подключены. SMTP настраивается отдельно.
> При проверке паспортной формы используйте данные, предназначенные для тестирования.

## Что работает

1. Поиск авиабилетов на выбранную дату. Карточки рейсов, время, длительность, цены.
2. Создание авиаброни с именем, фамилией, датой рождения, страной и номером документа, email.
   Полный номер документа после проверки **не сохраняется** — только маска с последними 4 символами.
3. «Мои авиаброни» внутри страницы авиабилетов: статусы, оплата, отмена.
4. Поиск отелей по городу, датам и гостям, карточки с рейтингом и удобствами, оформление и история броней.
5. Отдельное окно подтверждения заказа и экран успешного оформления с номером операции,
   суммой и адресом получателя письма. Микросервис фиксирует операцию, не обрабатывает её повторно
   и учитывает отмену.
   В шапке приложения есть кнопка «История оплат».
6. Подтверждение на email через SMTP, если настроен. Без SMTP письмо сохраняется
   в общей БД (`email_outbox`) как ожидающее отправки; оно не отправляется автоматически позже.
7. Единая БД SQLite для всех трёх процессов. Межсервисный RPC через отдельные очереди RabbitMQ.

## Запуск Windows 10/11

Требуются **Python 3.11+**, **Docker Desktop** с запущенным движком и подключение к интернету
для первой установки Python-библиотек.

Самый простой способ: дважды кликните **`ЗАПУСК_WINDOWS.bat`**. Он создаст окружение,
поставит зависимости, поднимет RabbitMQ и откроет приложение.

Или вручную в PowerShell из папки проекта:

```powershell
py -3 -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
docker compose up -d
python run_all.py
```

Если PowerShell запрещает запуск Activate.ps1, можно обойтись без активации:

```powershell
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe run_all.py
```

**Важно:** запускайте `run_all.py` из корневой папки проекта. Он открывает интерфейс и
запускает три отдельных процесса; после закрытия окна процессы завершаются.
RabbitMQ оставлен работающим до `docker compose down`.

### Проверка без GUI и RabbitMQ

```powershell
python -m unittest discover -s tests -v
```

Тесты проверяют поиск, авиабронирование, отели, обработку заказа, повторную операцию,
электронное подтверждение в очереди, отмену, валидацию данных и изоляцию по user_id.

## Архитектура

```text
                      PySide6 Desktop (Windows)
                              │ RPC JSON
                              ▼
                           RabbitMQ
             ┌────────────────┼────────────────┐
             ▼                ▼                ▼
      flights-service    hotels-service    payments-service
      поиск + мои брони  поиск + отели      подтверждение
             │                │                │
             └────────────────┼────────────────┘
                              ▼
                    data/travel.sqlite3
                       единая БД
                                              └── SMTP (если задан)
```

### Очереди и действия

| Сервис | Очередь | Действия `action` |
|---|---|---|
| Авиабилеты | `travel.flights.requests` | `search`, `book`, `list`, `cancel` |
| Отели | `travel.hotels.requests` | `cities`, `search`, `book`, `list`, `cancel` |
| Оплата | `travel.payments.requests` | `pay`, `list`, `outbox` |

Сообщение — JSON в UTF-8; ответ в `reply_to` с тем же `correlation_id`.
Код микросервисов: `services/`; база и общие функции: `common/`; интерфейс: `desktop/`.

## Отправка подтверждений на почту

Без настройки SMTP письма не отправляются, но сохраняются в `email_outbox`.
Для отправки писем понадобится пароль приложения в вашей почте. Обычный пароль аккаунта
использовать не рекомендуется. Настройте переменные в PowerShell **перед запуском**
(не записывайте пароль в исходники):

```powershell
$env:SMTP_HOST = "smtp.yandex.ru"
$env:SMTP_PORT = "465"
$env:SMTP_SSL = "true"
$env:SMTP_TLS = "false"
$env:SMTP_USER = "login"
$env:SMTP_PASSWORD = "пароль-приложения"
$env:SMTP_FROM = "login@yandex.ru"
.\ЗАПУСК_WINDOWS.bat
```

Для Mail.ru используйте `smtp.mail.ru` и полную почту в `SMTP_USER` и `SMTP_FROM`, порт `465`.
Для Rambler используйте `smtp.rambler.ru`, порт `465`, SSL, полный адрес для входа и
специальный пароль из **Настройки → Программы** после включения доступа почтовым клиентам.
При использовании сервера с STARTTLS можно задать `SMTP_PORT=587`, `SMTP_SSL=false`,
`SMTP_TLS=true`. Для Яндекс Почты может потребоваться включить доступ почтовым клиентам
в настройках ящика. Подставьте свою почту и пароль приложения.

Письмо отправляется на адрес, введённый в форме пассажира или бронирования отеля.
Экран успешного оформления показывает, отправлено ли письмо. Если SMTP недоступен,
подтверждение останется в `email_outbox` и будет отмечено как неотправленное.

Проверьте настройки вашего почтового провайдера. Письмо сообщает о статусе заказа.
Фискальный чек потребовал бы отдельной интеграции с онлайн-кассой.

## Подключение данных о реальных перелётах

В этой версии запросы уже подключены к публичному **Aviasales Data API** Travelpayouts.
Зарегистрируйтесь в Travelpayouts, подключите программу Aviasales, возьмите токен из
профиля и установите его как переменную окружения **до запуска**:

```powershell
$env:TRAVELPAYOUTS_TOKEN = "ваш_токен"
.\.venv\Scripts\python.exe run_all.py
```

Токен не записывайте в исходники и не публикуйте в чатах. Он передаётся через
заголовок `X-Access-Token` с сервера микросервиса `services/flight_provider.py`.
Если токен задан, программа **не подставляет локальные предложения**, даже когда API
вернул пустой ответ. Попробуйте другой маршрут/дату; учитывайте, что API содержит
только предложения, ранее найденные пользователями Aviasales.

**Data API** возвращает цены из кеша, то есть это не гарантированная цена покупки
в реальном времени. Кнопка «Проверить цену» открывает исходный поиск на Aviasales,
если ссылка присутствует в ответе API. Оформление в SkyWay создаёт внутреннюю
запись заказа и письмо; **не выписывает реальный билет и не списывает деньги**.

Реальный поиск в Aviasales Flight Search API доступен только проектам с подтверждённой
аудиторией от 50 000 активных пользователей в месяц. Этот API не выписывает билеты:
покупка идёт на стороне авиакомпаний или агентств.

Функция `common/catalog.py:demo_flights` используется только если токен не задан.
Адаптер `services/flight_provider.py` обрабатывает ошибки соединения, HTTP 401/403/429,
пустой ответ и формат данных; выдача настоящих билетов требует поставщика с правом выписки.

### Запуск через PyCharm

1. Откройте `travel-desktop` как проект.
2. Run → Edit Configurations → `+` → Python.
3. Script path: `run_all.py`; Working directory: папка `travel-desktop`;
   интерпретатор: `.venv\Scripts\python.exe`.
4. В **Environment variables** (при необходимости через Modify options) добавьте
   `TRAVELPAYOUTS_TOKEN` и `SMTP_HOST`, `SMTP_PORT`, `SMTP_SSL`, `SMTP_TLS`,
   `SMTP_USER`, `SMTP_FROM`, `SMTP_PASSWORD`.
5. Запускайте зелёной кнопкой. RabbitMQ из Docker Desktop должен работать заранее.

**Внимание:** переменные, заданные в отдельном PowerShell, автоматически не
переносятся в конфигурацию PyCharm. Значения секретов не включайте в скриншоты,
публичные проекты и общедоступные конфигурации.

## Данные и ограничения

- С токеном цены и рейсы загружаются из кеша Aviasales Data API;
  без токена используется встроенный каталог. Это не расписание авиакомпаний
  с подтверждённой доступностью мест.
- Данные отелей являются примерами; доступность номеров не отслеживается.
- ID пользователя сохраняется в настройках приложения на компьютере (QSettings).
  Авторизация отсутствует — это **не система для хранения реальных персональных данных**.
- SQLite — одна БД на одном компьютере. Для развёртывания сервисов на **разных компьютерах**
  нужна серверная БД, например PostgreSQL, и полноценная авторизация.
- В реальном приложении потребуются платёжный провайдер, фискализация, API-агентство для
  выписки билетов, API отелей, защищённое хранение ПДн и аудит. Это за рамками демонстрации.
